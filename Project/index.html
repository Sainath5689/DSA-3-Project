DSA METHODOLOGY

How the Algorithm Works

The system combines hashing, LSH and dynamic programming to identify similar questions.

01

Preprocessing

Questions are converted into a normalized form. Text is converted to lowercase and unnecessary punctuation is removed.

lowercase → clean → normalize
02

K-Shingling

Questions are divided into consecutive groups of words called k-shingles.

question → word shingles
03

Double Polynomial Hashing

Shingles are converted into numerical hash values using polynomial hashing.

shingle → hash₁ + hash₂
04

LSH Candidate Filtering

Locality-Sensitive Hashing reduces the number of question pairs requiring detailed comparison.

hash signatures → candidates
05

Exact Verification

Candidate questions are verified using a Dynamic Programming based comparison.

DP → similarity score
06

Classification

The calculated similarity is compared against a selected threshold to classify the pair.

score ≥ threshold → near duplicate

DSA PROJECT

Near-Duplicate Question Finder for Q&A Platforms

A data-structures-and-algorithms based system designed to identify questions that are similar or nearly identical.

Problem Statement

Q&A platforms can contain multiple questions that express the same or very similar information. Detecting these questions manually can be difficult when the dataset becomes large.

Objective

Develop an efficient algorithmic solution for identifying near-duplicate questions using shingling, hashing, LSH and exact verification.

Technologies

Java HTML5 CSS3 JavaScript CSV DSA

Project Modules

  • Question preprocessing
  • K-shingling
  • Double polynomial hashing
  • LSH candidate filtering
  • Exact verification
  • Result visualization
